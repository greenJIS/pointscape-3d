# Pointscape 3D

A web remake of the "Pointers" (Arrows) puzzle in enhanced 3D. Tap an arrow whose path out of the board is clear, and it
slides away. A blocked tap costs a heart. Clear the board to win. Two axes: five difficulties that set the grid size (Tiny 8x8,
Compact 12x12, Large 18x18, Vast 24x24, Massive 32x32) and five layer counts (1L to 5L), 25 tracks of 100 levels, 2,500 in total. There is no Undo anywhere.

Design documents, in reading order: `docs/srs.md` (requirements, with FR/N/P ids), `docs/plan.md` (reasoning and
research), `docs/ui-plan.md` (screens and UI rules). The requirements win if documents disagree. `docs/` is
gitignored, so these files exist only on the owner's machine and are not on GitHub.

## Environment

- Node 24, pinned in `.nvmrc`. Package manager: npm.
- Stack: React, TypeScript (`strict`), Vite, Tailwind CSS v4, three.js, Vitest, ESLint, Prettier.
- Published as static files on GitHub Pages by `.github/workflows/deploy.yml` on push to `main`. `vite.config.ts` sets
  `base` to `/pointscape-3d/`. The repository's Pages source must be "GitHub Actions".
- Local-only, gitignored: `docs/`, `.claude/`, `.husky/`, `.vscode/`. A fresh clone has no commit-msg hook until
  `.husky/commit-msg` (`npx --no -- commitlint --edit "$1"`) is recreated and `npm install` runs `husky`.
- Shell note: the owner's shell wraps `npm` and `npx` in Safe-chain, which can time out on installs with "Failed to
  check for malicious packages". Run `command npm install ...` or `command npx ...` to bypass it, but only with the
  owner's approval.

## Commands

- `npm run dev`: dev server. The developer unlock-all switch is only available here (FR-26).
- `npm run build`: type check, then production build to `dist/`.
- `npm test`: Vitest, once. `npm run test:watch` for watch mode.
- `npm run lint`, `npm run format:check`, `npm run format`. Prettier ignores `docs/`.

## Architecture

Three layers. Dependencies point downward only.

- `src/core/`: pure game logic. No three.js, React or browser APIs (N-1). Grid, rules, free-arrow test, solver,
  seeded level generator. Fully unit tested.
- `src/game/`: state, progress, settings, `isUnlocked()`, hint gifts, `localStorage` saving.
- `src/view/`: the three.js scene, picking, camera, arrow animation.
- `src/ui/`: React screens, modals and small parts (see `docs/ui-plan.md` section 7).

## Key decisions

- Arrows are straight or bent tubes with a barbed head. No groups of arrows in v1.
- A level is generated by reverse construction, so it is always solvable. Levels are seeded, so Try again and Restart
  give the same level.
- Every unlock rule goes through `isUnlocked()`. The UI never reads the developer flag itself.
- Clearing 10 levels (`UNLOCK_AFTER`) of a track opens its successors: the next layer count in the same difficulty, and
  (from a 1L track) the 1L track of the next difficulty. Tiny 1L opens Tiny 2L and Compact 1L; Tiny 2L opens only Tiny 3L.
- Player name: asked once, random animal name if skipped, editable in Settings, never cleared by Reset progress.
- Animation numbers come from guesses at the original game. They are meant to be tuned, so keep them in one table.
- The 3D view draws idle arrows as one merged mesh per layer (`BoardScene.syncBatched`). An arrow leaves the merged
  mesh while it animates, flashes, jiggles or pulses. Pick meshes sit on their own three.js layer so the camera skips
  them.
- Sound is synthesized with Web Audio in `src/view/sound.ts`. No audio files ship.
- Grid side comes from `SIDE` and arrow count from `DENSITY` (capped by `MAX_ARROWS`) in `src/core/levels.ts`, so the arrow
  count rises with the level number.

## Conventions

- Tailwind only, canonical class names, no CSS files besides the Tailwind entry (`src/index.css`, which holds the
  `@theme` colour tokens). `eslint-plugin-better-tailwindcss` enforces canonical classes in `.tsx` files, and
  `npm run lint -- --fix` fixes them. Its line-wrapping rule is off because Prettier owns wrapping.
- No `any` in TypeScript. `tsconfig.json` is `strict` plus `noUncheckedIndexedAccess`.
- Commits follow `type(scope): summary` and are checked by commitlint. Owner exception for this project: committing
  directly to `main` is allowed, so the global protected-branch rule does not apply here. Still commit only when
  asked.
- Do not add Claude or Anthropic co-author lines to commits or pull requests.
